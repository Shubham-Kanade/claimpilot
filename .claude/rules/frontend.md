# Frontend rules (Next.js PWA)

- **Next.js 16.4 App Router, TypeScript strict, Tailwind v4.** Server Components by default. Add `"use client"` only where interaction needs it.
- **Next 16.4 has breaking changes** from older versions: `cacheComponents` and `partialPrefetching` are on. Before using any Next API, read the relevant guide in `apps/web/node_modules/next/dist/docs/`, as `apps/web/AGENTS.md` instructs. Do not rely on memory of older Next versions.
- **API types are generated, never hand-written:**
  - Import them from `src/lib/api/schema.d.ts`, generated by `openapi-typescript` from the API's OpenAPI.
  - Use the thin typed client in `src/lib/api/client.ts`.
- **Streaming:** consume the agent and pipeline progress over SSE (typed events modeled on AG-UI). Keep the event parsing in one hook (`useClaimStream`).
- **Mobile-first and PWA:**
  - Camera capture via `<input type="file" accept="image/*,application/pdf" capture="environment" multiple>`.
  - Must work at a 360px width.
- **Accessibility:** semantic HTML, labelled controls, visible focus, colour is never the only signal (flags carry icon + text). The axe checks in Playwright must pass.
- **State:** server state via fetch + SSE. Claim UI state lives in a reducer (`claimReducer`) that is unit-tested.
- **UX principles:**
  - Show confidence per field.
  - Click a field to highlight its source on the receipt.
  - Ask at most one combined question at a time.
  - Never submit without an explicit confirm.
- **Tests:** Vitest + React Testing Library + MSW for units; Playwright for E2E (see `testing.md`).
