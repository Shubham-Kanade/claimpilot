# claimpilot-mcp-corp

The **mock corporate systems** ClaimPilot's agent consults: the HR directory, employee calendars and
the expense policy. A real MCP server (official Python `mcp` SDK, **streamable HTTP**) over seed
data. Synthetic data only; there is **no authentication**, so never expose it publicly (compose
publishes it on `127.0.0.1` only).

| | |
|---|---|
| Endpoint | `http://localhost:8102/mcp` (compose: `http://mcp-corp:8102/mcp`) |
| Health | `GET /healthz` (liveness), `GET /readyz` (directory loaded and policy file present) |
| Data | `seed/employees.json`, `seed/calendar.json`, the policy file |

## Run

```bash
cd services/mcp-corp
uv sync
uv run python -m claimpilot_mcp_corp
```

With Docker (from the repo root, the build context is the repo root): `docker compose -f
infra/compose.yml up --build -d --wait mcp-corp`.

| Variable | Default | |
|---|---|---|
| `SEED_DIR` | `<service>/seed` | folder with `employees.json` and `calendar.json` (`/app/seed` in the image) |
| `POLICY_PATH` | unset | the policy file. Unset: `seed/policy.yaml`, then `services/api/config/policy.yaml` |
| `MCP_HOST` | `127.0.0.1` | bind address (`0.0.0.0` in the image) |
| `MCP_PORT` | `8102` | |
| `LOG_LEVEL` | `info` | |

The **canonical policy** is `services/api/config/policy.yaml`. The image copies it to
`seed/policy.yaml` at build time; in a checkout the server reads it in place. If no file is found
the policy tool and resource answer `policy not available` (and `/readyz` says 503) instead of
crashing.

## Tools and resource

| Tool | Arguments | Result |
|---|---|---|
| `get_employee` | `employee_id` (directory id `P001` **or** HR number `EMP85968`) | `{id, name, employee_id, grade, base_city, base_state_code, manager_id, email}` |
| `list_employees` | none | `{result: [employee]}` |
| `search_calendar` | `employee_id` (either id), `start_date`, `end_date` (ISO dates, inclusive) | `{result: [event]}`, oldest first |
| `get_policy` | none | `{result: "<policy text>"}` |

* Resource `policy://expense/v3`: the same policy text (`application/yaml`); the tool mirrors it for
  clients that cannot read resources.
* An **event** is `{id, title, date, end_date, start_time, end_time, location, attendees[], kind}`
  with `kind` one of `client_meeting`, `client_dinner`, `offsite`, `training`, `travel`. Multi-day
  events (trips, offsites) have `end_date` and no times, and match any day they span.
* Unknown employees, a backwards date range or a range over 366 days are readable tool errors.
* Employees are the five golden-set personas (`P001`-`P005`) plus three fictional demo personas
  (`DEMO-ASHA` Asha Menon L3 Pune, `DEMO-RAVI` Ravi Iyer L5 Bengaluru, the approver, and
  `DEMO-MEERA` Meera Shah L2 Mumbai). Ravi is everyone's `manager_id`.

## The seed

`seed/*.json` is generated by `scripts/build_seed.py` from `data/synth/golden` and is committed:

```bash
uv run python scripts/build_seed.py           # rewrite the seed (deterministic, idempotent)
uv run python scripts/build_seed.py --check   # exit 1 if the committed seed is stale
```

* About 60% of each persona's `client_entertainment` receipts (chosen by a stable hash of the
  document id) get a `client_dinner` event on the receipt's date, at the receipt's venue, with 2-4
  fictional attendees from one fictional client company. The other ~40% get **no event on
  purpose**, so the agent still has something to ask the user. For the seven golden dinners that is
  4 with an event and 3 without.
* Every trip (`trip_id`) gets one `travel` event spanning its receipts' dates.
* The demo personas carry a few hand-written events around the 12 Oct 2026 deadline.
* The unit tests fail if the committed seed differs from what the script produces.

## Tests

```bash
uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run pytest --cov
```

Unit tests cover lookup by both ids, calendar filtering (inclusive ranges, multi-day overlap,
ordering), seed integrity against the golden receipts, the builder, and the tool surface; the
integration tests start the server on a free port and drive it with the real MCP client (tools,
the policy resource, health, both protocol generations). They use a tiny policy fixture, never the
real file. Coverage gate: 90%.
